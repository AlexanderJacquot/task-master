# task-master 0.31.0

Scribe fixes for Windows, a way to measure transcription speed, and a tidier sidebar.

**Database schema 23**, as in 0.29 and 0.30: no migration. Keep your sync server on the
same version as your desktops all the same.

## Scribe

- **Recordings play on Windows again.** The Play button did nothing: the app's security
  policy (CSP) had no rule for media, so the window refused the recording's audio. It now
  allows it. If a recording still cannot play, the player says why instead of doing
  nothing.
- **Transcription progress moves as it goes.** The bar used to move only after each five
  minutes of speech were transcribed. On a computer without a supported graphics card
  (Windows for now) that takes minutes, so a transcription looked stuck. The bar now
  moves after every 30 seconds of audio. The row also shows how long the transcription
  has run and, at its pace so far, about how long is left.
- **`scribe.log`.** Each transcription adds lines to `scribe.log` in the data folder (on
  Windows `%APPDATA%\space.solarnexus.taskmaster`, unless you moved it): the model, the
  number of threads and the processor features the speech engine uses, then every stage
  (reading the audio, loading the model, finding speech, each chunk, telling voices apart)
  with how long it took and how many times faster than real time it ran.
- **Fewer threads.** Transcription now uses about one thread per physical core (half the
  logical ones, at most 8) instead of all but one, since the engine's threads wait for
  each other and hyper-threads mostly add waiting. The `TM_SCRIBE_THREADS` environment
  variable sets another count, to compare in `scribe.log`.

## Sidebar

- A light rule separates the projects. Every fold chevron hangs in the left gutter, so the
  row icons line up with the navigation icons. Unfolded sections show a guide line, like
  note folders.

## For contributors

- The ignored test `real_models_transcribe_a_recording` doubles as a benchmark: it prints
  each stage's time; `TM_SCRIBE_WHISPER` picks the model file (see `pipeline.rs`).
- The playback cause was found by reading the CSP and Tauri 2.12.5's CSP handling. It has
  been tested in jsdom, not yet on a Windows machine.
