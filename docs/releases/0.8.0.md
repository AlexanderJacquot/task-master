# task-master 0.8.0

## Plan work in Lineage

- Filter the graph by project, tag, completion, readiness or connected tasks. Finished
  tasks and links fade; open tasks show how many prerequisites still block them.
- Add a prerequisite or dependent from a card, creating a task or linking an existing one.
  A new linked task is one undoable change. Open a task's own lineage from its details.
- Boards fit unsized status columns to the available width, while keeping manually chosen
  widths. Middle-button dragging pans a board, and search is available in list and board
  views.

## Agent sessions

- Choose what status a task enters when sent to an agent and when the agent finishes.
  Pick a model for a session, or use the model from agent settings.
- Agents may mark the user's subtasks done. `complete_session` asks them to finish each
  open subtask or explicitly list it as left open, so unfinished work stays visible.
- Continue a running session in a real terminal. The terminal resumes the conversation
  with its model, permission mode and task tools, and continues an interrupted turn.
  Terminal launching from the Linux AppImage now restores the host environment.

## Desktop refinements

- Linux draws its own title bar. The sidebar can be resized, and projects can use engraved
  icon marks. Long task titles grow to show their full text in WebKitGTK.
- Task pages avoid a second weathering layer; opening a newly created task from the
  panel keeps the cursor in its description. The calendar's today marker is round.
- Windows sign-in can use another callback port if the first is reserved.

## Server and upgrade

This release upgrades the database to **schema 12** for the agent session model. Upgrade
the sync server and desktops together: replicas at different schema versions do not sync.
The matching server image is `ghcr.io/alexanderjacquot/task-master-server:v0.8.0`.

Installed desktops can update from **Settings → About → Check for updates**. New
installations use the Windows setup executable, macOS DMG, or Linux AppImage/DEB/RPM.
Updates are signed; installers are not platform code-signed. The AUR package publish step
remains pending account registration; the release installers are unaffected.
