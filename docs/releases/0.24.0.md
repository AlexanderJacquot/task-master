# task-master 0.24.0

Claude sessions beyond the app's own: the ones you run in a terminal now count on the
Agents page, and "Send to agent" can open a task in the Claude desktop app. Plus fixes
found testing agents on macOS.

## Sessions run in a terminal

- Claude Code sessions you run yourself, outside the app, now count on the **Agents** page
  with the app's own: cost, time worked and requests, read from the transcripts Claude
  Code keeps (`~/.claude/projects`, or inside WSL when agents run there). Every 5 minutes,
  or at once with **read them now**.
- Each one is filed under the project whose folder holds it (project folders are set on
  this device); pick another project by hand in **Recent sessions**, or remove a row.
- The **Sessions** filter shows all sessions, those sent from tasks, or those run in a
  terminal. Spend limits count both, Send to agent included.
- Settings → Agents → Terminal turns the import off.

## Sessions in the Claude desktop app (macOS and Windows)

- **Send to agent → Run → In the Claude desktop app**: **Open in Claude** opens a new Code
  session in the Claude desktop app, in the task's folder, with the task and the app's
  rules typed in. You press Send there and pick the permissions and model there.
- The session shows **In desktop app** until Claude records its summary or you click
  **Mark done**. Its notes and summary reach the task when the desktop app has
  task-master's MCP (the claude.ai connector, or the local server: `claude mcp add`, see
  docs/mcp.md).
- With the local server, the conversation is linked to the session: its time and turns
  come from its transcript, and its cost once the desktop app has written it there (it
  does so only now and then). A finished one can be continued with **Open in terminal**.
- The first time the desktop app opens a folder it asks you to trust it; send the prompt
  again after that.
- The choice is remembered. Not on Linux, nor with agents in WSL.

## Fixes

- **Open in terminal** on macOS while Terminal was not running marked the session done at
  once and left its Claude running. It now stays "In terminal" until Claude records its
  summary, you mark it done (which stops Claude), or you quit Claude there.
- Sessions continued in a terminal after the desktop app keep task-master's tools and are
  stopped by **Mark done**.
- Sessions from the desktop app get a time worked even when their transcript has no other
  measure of it.

## Compatibility

- Database schema 17 (terminal sessions): update desktops and the sync server together.
- Server image: `ghcr.io/alexanderjacquot/task-master-server:v0.24.0`.
