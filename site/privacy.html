Privacy policy

Effective date: 6 November 2026

This policy covers the task-master desktop application, its optional Google Calendar integration and self-hosted sync server, and this project website. The project is maintained by Alexander Jacquot.

1. Tasks and local storage

Tasks, descriptions, projects, tags, attachments, schedules, and change history are stored on your device. The desktop app does not require a hosted task-master account for local use. The app does not send this content to project maintainers by default.

2. Google Calendar data and permissions

Connecting Google Calendar is optional. After you authorize access through Google in your browser, task-master uses these permissions:

Create and manage calendars created by the app
The calendar.app.created scope lets task-master create its dedicated calendar and manage events in calendars it creates. The integration writes scheduled tasks, day plans, and due dates to the task-master calendar.
Read your calendar list
The calendar.calendarlist.readonly scope provides calendar identifiers, names, colors, and related metadata so you can choose calendars to display.
Read calendar events
The calendar.events.readonly scope lets the app display events and detect changes to its synced events. The app processes event identifiers, titles, dates and times, locations, event links, update metadata, and sync identifiers.

Google receives task titles, planned dates, time blocks, due dates, completion markers, generated event descriptions, and identifiers needed to match events to tasks. Full task descriptions and attachments are not included in the Calendar events created by this integration.

Calendar data is used to display your calendar and synchronize the schedules and due dates you manage in task-master. It is not sold, used for advertising, or used to train AI models.

task-master's use and transfer of data received from Google APIs follows the Google API Services User Data Policy, including its Limited Use requirements.

3. Where Calendar data and credentials are stored

When Calendar runs on your desktop, OAuth client settings, a refresh token, and cached Calendar data are stored locally. The refresh token lets the app keep syncing without asking you to sign in for every update. Google handles your password; task-master does not receive it.

If you choose Runs on → Server, the app transfers the OAuth client settings and refresh token to your configured sync server. That server calls Google and stores the Calendar cache, and your connected desktop reads the Calendar data from it. The server operator can access the data stored on that server.

Moving Calendar back to the desktop does not automatically erase the server's retained credential file. To remove all server copies, the server operator must separately remove retained credentials and any backups.

4. Optional sync, backups, and other services

If you enable device sync, task data and attachments are transferred to the server you configure and to devices connected to it. Changes imported from Google into your task schedules or due dates can also synchronize to those devices.

If you enable remote backups, database backups and attachments can be sent to the S3-compatible storage you configure. Database backups may contain cached Calendar data and task history. Server Calendar credentials are stored separately from its database backups.

The project does not operate a mandatory hosted storage service for your tasks. Google, your selected server and backup providers, and any identity provider you configure process data according to their own terms and settings.

Update checks and downloads contact GitHub and may expose ordinary connection information, such as your IP address, to GitHub. They do not upload your task or Calendar content.

5. Security

Google API requests use HTTPS. The application uses browser-based authorization with PKCE and stores credentials outside its task change history. task-master does not encrypt its local database or credential files; protection also depends on your device's file permissions and any disk encryption you configure. Security of optional server and backup connections depends on how you configure and operate them.

6. Retention, disconnecting, and deletion

To stop Calendar syncing, use Settings → Calendar → Disconnect. If Calendar runs on the server, move it to This device first. Disconnecting removes the desktop's stored refresh token and current Calendar cache and requests token revocation from Google. OAuth client settings are kept for reconnecting.

You can also revoke access in your Google Account connections. Previously created events remain in Google Calendar until you delete them there. Disconnecting does not remove your task data.

Task deletion can leave records in undo history, synchronized copies, exports, and backups. To remove all copies of your information, also remove the relevant application data, configuration, exports, backups, and any server copies you control. Backup retention depends on the storage and settings you use.

7. This website and support

These pages contain no project analytics, tracking scripts, advertising, or forms that collect Calendar data. The website is hosted on GitHub Pages. GitHub logs visitor IP addresses for security and handles hosting information under the GitHub General Privacy Statement.

If you contact the project through GitHub, information you choose to submit is handled by GitHub and may be public. Project maintainers receive the content you choose to share there; this is separate from the app's local task and Calendar storage.

8. Contact and changes

For privacy questions, contact maintainer Alexander Jacquot through the contact methods on his GitHub profile. General questions can be raised on the project support page. Please do not post personal calendar data, credentials, or tokens in public issues. If you configured your own Google OAuth client, its support email belongs to that client owner.

Changes to this policy will be published on this page with an updated effective date. Any future expansion of Google data use must be disclosed before that new use and authorized when required.
